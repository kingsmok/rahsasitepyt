  🚀 آکادمی آنلاین — نصب خودکار (مثل وردپرس)
═══════════════════════════════════════════════════════════════

🔹 روش نصب — ۳ قدم:

  قدم ۱) آپلود:
    محتوای این پوشه را در هاست آپلود کنید
    (public_html یا /home/user/domain.com)

  قدم ۲) محیط مجازی (یک بار):
    python3 -m venv venv
    ./venv/bin/pip install -r requirements.txt

  قدم ۳) فایل .htaccess (از deploy/passenger.htaccess):
    PassengerAppRoot /home/کاربر/پوشه‌پروژه
    PassengerPython  /home/کاربر/پوشه‌پروژه/venv/bin/python
    PassengerAppEnv  production

  سپس آدرس سایت را باز کنید:
    https://دامنه‌شما.com/install
  ← نصب‌کننده باز می‌شود (مشابه وردپرس):

  ┌─────────────────────────────────────────────┐
  │ گام ۱: دیتابیس                              │
  │   ● SQLite (بدون تنظیم — برای شروع)        │
  │   ● MySQL  (آدرس/نام/کاربر/رمز از پنل هاست)│
  │   دکمه «تست اتصال» → تأیید                  │
  │ گام ۲: حساب مدیر (نام/ایمیل/رمز)           │
  │   + گزینه ساخت دانشجوی نمونه                │
  │ گام ۳: اطلاعات سایت (نام/شعار/تلفن/ایمیل)  │
  │   → دکمه «شروع نصب»                         │
  └─────────────────────────────────────────────┘

  خودش انجام می‌دهد:
  ✓ اتصال دیتابیس + ساخت ۶۵ جدول
  ✓ حساب مدیر (super_admin) + دانشجوی نمونه
  ✓ ۸ دسته‌بندی + صفحه اصلی حرفه‌ای
  ✓ یک دوره نمونه رایگان (با درس‌ها)
  ✓ کوپن WELCOME20 + تنظیمات اولیه
  ✓ فایل .env (SECRET_KEY امن + DATABASE_URL)
  ✓ بستن مسیر /install بعد از نصب

───────────────────────────────────────────────────────────────
🔹 نکات:
  • بعد از نصب، لاگین مدیر → /admin (با 2FA دمو)
  • تنظیمات کامل: پنل ادمین ← ⚙️ تنظیمات سوپر
  • انتقال داده از سایت قبلی (SQLite → MySQL):
      python3 scripts/migrate_sqlite_to_mysql.py
  • اگر نصب را پاک کنید (instance/.installed را حذف
    کنید) نصب‌کننده دوباره فعال می‌شود.

  🔧 عیبیابی — اگر خطای 500 دیدید:
═══════════════════════════════════════════════════════════════

۱) **نسخه پایتون هاست**: این پروژه با پایتون 3.8 تا 3.13
   سازگار است. اگر هاست شما پایتون 3.7 یا قدیمیتر دارد
   نسخه را ارتقا دهید (پنل هاست → نسخه پایتون).

۲) **محیط مجازی**: حتماً venv ساخته و پکیجها نصب شده باشند:
     python3 -m venv venv
     ./venv/bin/pip install -r requirements.txt

۳) **پرمیشن پوشهها** (مهم — علت رایج 500):
     chmod -R 775 instance logs
     (هاست باید بتواند در instance بنویسد — دیتابیس آنجاست)

۴) **.htaccess**: مسیر PassengerAppRoot و PassengerPython
   دقیقاً مطابق مسیر واقعی هاست باشد.

۵) **لاگ خطا**: در پنل هاست (Error Logs) یا فایل:
     logs/error.log  و  logs/academy.log
   آخرین خط Traceback را ببینید.

۶) اگر سایت نصب شده و ناگهان 500 داد:
   دیتابیس/تنظیمات را از پنل ادمین ← بکاپ بررسی کنید.
   برای شروع دوباره: فایل instance/.installed را حذف کنید
   تا نصبکننده دوباره فعال شود.

  🗄 عیبیابی اتصال MySQL (پیامهای خطا + راهحل)
═══════════════════════════════════════════════════════════════

  ❌ «Can't connect to MySQL server on ...» (کد 2003)
     آدرس (Host) اشتباه است یا سرور MySQL در دسترس نیست.
     ✅ از پنل هاست آدرس دقیق را بردارید — اکثر هاستها: localhost
        (در cPanel: بخش Databases → اطلاعات دیتابیس)

  ❌ «Access denied for user ...» (کد 1045)
     نام کاربری یا رمز اشتباه است.
     ✅ کاربر و رمز را از همان صفحهای که دیتابیس را ساختهاید کپی کنید.
        (کاربر معمولاً به شکل user_ نام کاربری پنل است)

  ❌ «Access denied ... to database» یا «Unknown database» (1044/1049)
     دیتابیس ساخته نشده یا کاربر به آن وصل نیست.
     ✅ در پنل هاست دیتابیس را بسازید (character set: utf8mb4)
        و کاربر را به آن وصل کنید (Add User To Database).

  ❌ نام دیتابیس/کاربر/رمزی که با @ # ! شروع میشود
     حالا خودکار encode میشود — مشکلی نیست.

  ⚠️ در فرم نصب فقط اینها را وارد کنید:
     Host:     localhost  (یا آدرس پنل — بدون @ و # و فاصله)
     Port:     3306
     Database: فقط نام دیتابیس (مثل academy)
     Username: فقط نام کاربری
     Password: رمز واقعی — هر کاراکتری مجاز است

═══════════════════════════════════════════════════════════════
  🗄 عیبیابی: «Lost connection to MySQL server during query» (2013)
═══════════════════════════════════════════════════════════════

  این خطا یعنی اتصال اولیه برقرار شده ولی هنگام ساخت جدول‌ها/
  داده‌ها، سرور MySQL اتصال را قطع کرده. علت: محدودیت هاست.

  راه‌حل‌ها (به ترتیب):
  ۱) max_allowed_packet هاست را بالا ببرید (مهم‌ترین):
     - cPanel → MySQL → یا phpMyAdmin → Variables → max_allowed_packet
       به 64M یا بیشتر
     - یا از پشتیبانی هاست بخواهید (روی هاستینگر: تیکت پشتیبانی)
  ۲) دوباره روی «شروع نصب» بزنید — نسخه جدید از همان‌جا ادامه
     می‌دهد (جدول‌های ساخته‌شده را رد می‌کند) و با تراکنش‌های
     کوچک + تلاش مجدد خودکار کار می‌کند.
  ۳) اگر هاست MySQL خیلی محدود است، از SQLite استفاده کنید
     (گام ۱ فرم نصب) — بدون نیاز به MySQL.

  🆘 اگر باز هم 500 دیدید — این راهنما را قدم‌به‌قدم بروید
═══════════════════════════════════════════════════════════════

  حالا دیگر 500 بی‌دلیل نمی‌بینید:
  • اگر پکیج‌ها نصب نباشند → صفحه راهنما با دستور نصب می‌بینید
  • اگر نصب ناقص باشد → به /install ریدایرکت می‌شوید با دکمه
    «🔧 تعمیر دیتابیس» (جدول‌ها را بدون پاک کردن داده می‌سازد)
  • همه پاسخ‌های نصب‌کننده JSON است — هیچ JSON.parse نمی‌شکند

  ۱) آپلود و استخراج بسته جدید
  ۲) python3 -m venv venv
  ۳) ./venv/bin/pip install -r requirements.txt
  ۴) chmod -R 775 instance logs
  ۵) .htaccess (مثل قبل) + touch passenger_wsgi.py
  ۶) دامنه/install را باز کنید:
     - بالای صفحه «🩺 بررسی سلامت سرور» را ببینید
     - اگر چیزی ❌ بود، همان پیام را برای پشتیبانی بفرستید
     - اگر همه ✅ بود، فرم را پر و نصب را بزنید
  ۷) اگر بعد از نصب سایت 500 داد، دامنه/install را باز کنید —
     دکمه تعمیر را بزنید.

  ⚡ نسخه جدید — نصب تکه‌ای بدون thread پسزمینه
═══════════════════════════════════════════════════════════════
  بعضی هاستهای cPanel/Passenger بعد از پایان پاسخ HTTP، thread
  پسزمینه را متوقف می‌کنند و پیام «نصب قطع شد» دیده می‌شد.

  حالا:
  • هر درخواست فقط چند جدول را می‌سازد و سریع تمام می‌شود
  • مرورگر خودکار درخواست کوتاه بعدی را می‌فرستد
  • جدولها و seed کاملاً idempotent هستند و از همانجا ادامه می‌دهند
  • هیچ رمز دیتابیس/مدیری در فایل progress ذخیره نمی‌شود
  • اگر ارتباط قطع شود دکمه «ادامه نصب» همان صفحه نمایش داده می‌شود
  • وقتی تمام شد خودکار وارد سایت می‌شود
  → نه Request Timeout داریم و نه وابستگی به background thread

  دکمه «تست اتصال» هم سریع شد:
  • چک DNS فوری (هاست خراب در <۰.۱ ثانیه رد میشود)
  • سقف ۲۰ ثانیه در مرورگر + پیام خوانا

═══════════════════════════════════════════════════════════════
  🗄 اگر «Lost connection during query (2013)» دیدید
═══════════════════════════════════════════════════════════════
  نسخه جدید خودش این را مدیریت میکند:
  • بعد از هر اتصال، سقف زمان کوئری هاست (max_statement_time /
    max_execution_time) برای سشن صفر میشود — کوئریهای سنگین
    (ساخت جدول با ایندکس) دیگر kill نمیشوند
  • ساخت جدولها جدولبهجدول با تلاش مجدد خودکار — اگر اتصال قطع
    شد، فقط همان جدول دوباره ساخته میشود (نه از اول)
  • هر بار که خطا دیدید روی «شروع نصب» بزنید — از همانجا ادامه
    میدهد (جدولهای ساختهشده میمانند)

  اگر باز هم 2013 گرفتید:
  ۱) پشتیبانی هاست: بخواهید max_statement_time روی 0 باشد
  ۲) یا در گام اول «SQLite» را انتخاب کنید — روی هر هاستی
     بدون هیچ محدودیتی کار میکند

═══════════════════════════════════════════════════════════════
  ⚡ نسخه فوقسریع — نصب در ۳-۴ ثانیه
═══════════════════════════════════════════════════════════════
  تغییرات این نسخه:
  • اتصال: TCP → اگر نشد خودکار سوکت محلی (هاستهایی که فقط
    socket دارند هم وصل میشوند)
  • دادهها با batch insert (چند ردیف در یک کوئری) کپی میشوند
    بهجای درج تکتک — دهها برابر سریعتر
  • FOREIGN_KEY_CHECKS=0 هنگام درج (چند برابر سریعتر)
  • یک اتصال واحد برای کل نصب (بدون reconnect بین مراحل)
  • جدولها جدولبهجدول با تلاش مجدد خودکار

  نتیجه: نصب کامل (۶۵ جدول + همه دادهها) ≈ ۳-۴ ثانیه —
  خیلی کمتر از سقف زمانی هر هاست اشتراکی.

  🔁 اگر صفحه «در حال نصب...» گیر کرد
═══════════════════════════════════════════════════════════════
  این نسخه سه حالت گیرکردن را خودش حل میکند:
  ۱) چند-worker هاست: پیشرفت نصب به‌صورت اتمیک در فایل
     instance/.install_progress.json ذخیره می‌شود و هر worker می‌بیندش.
  ۲) Passenger دیگر چیزی برای متوقف‌کردن ندارد: نصب در thread
     پسزمینه اجرا نمی‌شود و هر تکه داخل یک درخواست کوتاه کامل می‌شود.
  ۳) اگر صفحه رفرش یا ارتباط قطع شود، فرم «آماده ادامه» را نشان
     می‌دهد؛ رمز مدیر را دوباره تأیید و شروع/ادامه را بزنید.
     جدول‌های قبلی حفظ می‌شوند و هیچ مرحله‌ای از ابتدا تکرار نمی‌شود.

  🔴 اگر «هیچ دکمه‌ای کار نمی‌کند» → این نسخه را نصب کنید
═══════════════════════════════════════════════════════════════
  نسخه قبلی یک خطای جاوااسکریپت داشت که کل اسکریپت نصب‌کننده
  را از کار می‌انداخت (دکمه‌ها بی‌جواب می‌ماندند). این نسخه:
  • جاوااسکریپت کاملاً بازنویسی و با node تأیید شد (بدون خطا)
  • همه دکمه‌ها تست شدند: تست اتصال / شروع نصب / تعمیر / پنل سلامت
  • نصب SQLite و MySQL هر دو تست شد (۶۵ جدول در ۳.۶ ثانیه)

  نصب: کل بسته را آپلود کنید و touch passenger_wsgi.py

═══════════════════════════════════════════════════════════════
  🔄 دکمه بروزرسانی از گیت (در تنظیمات سوپر)
═══════════════════════════════════════════════════════════════
  بعد از نصب، در «پنل ادمین ← تنظیمات سوپر ← تب 🔄 بروزرسانی»
  دکمه «بروزرسانی از گیت» را دارید که:
  ۱) آخرین نسخه را از مخزن گیت دریافت میکند (git fetch)
  ۲) کدها را جایگزین میکند (git reset --hard)
  ۳) دیتابیس را مایگریشن میکند (جدولها و ستونهای جدید خودکار)

  برای کارکرد آن روی هاست:
  ۱) پروژه باید یک مخزن گیت باشد:
       cd /home/user/domain.com
       git init
       git remote add origin https://github.com/USER/REPO.git
  ۲) آدرس مخزن را در «تنظیم مخزن» (همان صفحه) وارد کنید
     یا ریموت origin خودش خوانده میشود.
  ۳) گارد ایمنی: اگر مخزن اشتباه باشد (بدون app.py) بروزرسانی
     متوقف میشود — پروژه نابود نمیشود.
