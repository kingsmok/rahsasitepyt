## ۱) app.py — ۹۰۷ خط (هسته برنامه)

**نقش:** Application Factory + middleware سراسری (CSRF، rate limit، حفاظت فایل، gzip، کش، هدرهای امنیتی) + فیلترهای Jinja + ثبت بلوپرینتها + error handler ها

**نقاط قوت (واقعی):**
- ✅ App Factory pattern درست — `create_app()` تستپذیر (۲۵ pytest روی دیتابیس موقت)
- ✅ CSRF سراسری با توکن سشن + معافیت صحیح `/api` و `/builder/api` (JSON)
- ✅ Rate limit Redis-ready: `REDIS_URL` → Redis INCR/EXPIRE، بدون → حافظه با قفل threading
- ✅ حفاظت فایلها: `/static/uploads` و `/uploads` هر دو، با چک نقش/مالکیت
- ✅ gzip برای HTML/CSS/JS + کش خصوصی صفحات عمومی
- ✅ لاگ ساختاریافته (RotatingFileHandler 5MB×5) + python-dotenv + SESSION_COOKIE_SECURE خودکار در production + MAX_CONTENT_LENGTH 50MB
- ✅ error handler: 400/403/404/405/413/500

**مشکلات قطعی:**
| # | مشکل | شدت |
|---|---|---|
| A1 | `render_error()` برای 400/413 از قالب استفاده میکند که به `g.cart` نیاز دارد — اگر خطا قبل از `load_globals` رخ دهد 500 آبشاری میشود (فعلاً در عمل رخ نمیدهد چون load_globals قبل از route هاست، ولی شکننده است) | Low |
| A2 | `_rate_limit` روی `/auth/login` با IP پشت proxy — فقط `X-Forwarded-For` اول را میخواند؛ اگر nginx درست تنظیم نشود قابل جعل است | Medium |

**مشکلات احتمالی:** `_ttl_cache` در حافظه — با چند worker گunicorn هر worker کش جدا دارد (قابل قبول، فقط ناکارآمد نه غلط)

**ریسک امنیتی:** A2 — سناریو: مهاجم هدر `X-Forwarded-For: 1.2.3.4` جعل کند → rate limit دور زده شود. راهحل: اعتماد به `X-Forwarded-For` فقط وقتی nginx آن را overwrite کند (تنظیم `proxy_set_header X-Forwarded-For $remote_addr`).

**بدهی فنی:** ۹۰۷ خط در یک فایل — پیشنهاد: استخراج `middleware.py` (هدرها/rate limit/حفاظت فایل) و `filters.py`

**نمونه اصلاح (A2):**
```python
# در production فقط از IP مستقیم استفاده کن (nginx X-Forwarded-For را اعتبارسنجی میکند)
ip = request.remote_addr or 'unknown'
if os.environ.get('TRUST_PROXY') == '1':
    ip = request.headers.get('X-Forwarded-For', ip).split(',')[0].strip()
```

## 🐛 باگ آبشاری پیدا و رفع شد (باگ جدی)

**مشکل:** POST بدون توکن CSRF → 500 (بجای 400). علت: `abort(400)` از `csrf_protect` (که قبل از `load_globals` اجرا میشود) → errorhandler 400 قالب رندر میکرد → **context processor ها به `g.user` دسترسی داشتند که ست نشده بود** → AttributeError → 500.

**رفع:** همه دسترسیهای `g.user` در context processor ها → `getattr(g, 'user', None)` + `g.cart/g.cart_count/g.theme/g.pages` → getattr + after_request ایمن شد.

**تست regression:** `test_csrf_rejection_returns_400_not_500` — اضافه شد (۲۷ pytest سبز).
