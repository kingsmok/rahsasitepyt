# 🐬 بهینه‌سازی دیتابیس MySQL (phpMyAdmin) — راهنمای عملی

> برای سایت آکادمی آنلاین — بعد از اصلاحات کد (کاهش کوئری‌ها از ۱۵۴۲ به ۲۵)،
> حالا نوبت بهینه‌سازی سمت دیتابیس MySQL است تا کوئری‌های باقی‌مانده هم
> با ایندکس مناسب در چند میلی‌ثانیه اجرا شوند.

---

## چرا ایندکس این‌قدر مهم است؟

بدون ایندکس، MySQL برای هر جستجو باید **کل جدول را اسکن کند** (مثلاً ۵۰ هزار
سفارش را یکی‌یکی بخواند). با ایندکس، مثل فهرست انتهای کتاب، مستقیم می‌رود سراغ
ردیف‌های موردنظر:

| کوئری | بدون ایندکس | با ایندکس |
|---|---|---|
| تیکت‌های باز کاربر | اسکن ۱۰ هزار ردیف ~ ۱ ثانیه | چند ردیف ~ ۱ میلی‌ثانیه |
| سفارش‌های کاربر (مرتب با تاریخ) | مرتب‌سازی کامل جدول | خواندن مستقیم |
| اعلان تکراری یادآورها | اسکن کل جدول اعلان‌ها | چند ردیف |

---

## مرحله ۱ — بکاپ (الزامی!)

در phpMyAdmin:
1. روی نام دیتابیس کلیک کنید → تب **Export** (خروجی)
2. روش **Quick** → فرمت **SQL** → دکمه **Go**
3. فایل خروجی را در جای امن نگه دارید

## مرحله ۲ — اجرای اسکریپت بهینه‌سازی

فایل آماده: **`deploy/mysql-optimize.sql`**

1. در phpMyAdmin دیتابیس خود را انتخاب کنید
2. تب **SQL** را باز کنید
3. محتوای فایل `mysql-optimize.sql` را کپی کرده و در کادر بچسبانید
4. دکمه **Go** / **اجرا** را بزنید

این اسکریپت:
- ✅ **ایندکس‌های جاافتاده** را می‌سازد (فقط آن‌هایی که نیستند — اجرای مجدد بی‌خطر است)
- ✅ **ANALYZE** می‌کند تا موتور MySQL از ایندکس‌های جدید استفاده کند
- ✅ **OPTIMIZE** جدول‌های داغ (فشرده‌سازی — بهتر است در ترافیک کم اجرا شود)
- ✅ لاگ‌های 404 قدیمی‌تر از ۹۰ روز را پاک می‌کند (جدولی که ربات‌ها بزرگش می‌کنند)

## مرحله ۳ — به‌روزرسانی کد (ایندکس‌سازی خودکار)

کد به‌روزشده در اولین اجرا، ایندکس‌های جاافتاده را **خودکار** هم می‌سازد
(تابع `ensure_indexes` در `models.py`). فقط کد جدید را روی سرور بگذارید و ری‌استارت کنید.

همچنین در فایل `.env` تنظیمات اتصال MySQL را بررسی کنید:

```env
# اتصال‌های هر ورکر — برای هاست اشتراکی ۵ و ۱۰ امن است
MYSQL_POOL_SIZE=5
MYSQL_MAX_OVERFLOW=10
```

> ⚠️ اگر در لاگ‌ها خطای `Too many connections` دیدید، این دو عدد را کمتر کنید (مثلاً ۳ و ۵).
> قبلاً ۳ ورکر × ۳۰ اتصال = **۹۰ اتصال** بود که از سقف هاست‌های اشتراکی رد می‌شد و خطای 500 می‌داد!

## مرحله ۴ — تنظیمات سرور MySQL (بهترین برد سرعت)

فایل نمونه: **`deploy/mysql-recommended.cnf`**

- اگر سرور اختصاصی/VPS دارید: فایل را در `/etc/mysql/conf.d/` بگذارید و ری‌استارت کنید
- اگر هاست اشتراکی دارید: همین مقادیر (مخصوصاً `innodb_buffer_pool_size`) را از
  پشتیبانی هاست بخواهید — معمولاً بدون هزینه انجام می‌دهند

مهم‌ترین‌ها: `innodb_buffer_pool_size` (حدود ۵۰٪ رم) و `innodb_flush_log_at_trx_commit = 2`.

## مرحله ۵ — اطمینان از کارکرد ایندکس‌ها (EXPLAIN)

در phpMyAdmin، تب SQL، یک کوئری واقعی را با `EXPLAIN` جلویش تست کنید:

```sql
EXPLAIN SELECT * FROM tickets
WHERE user_id = 5 AND status IN ('open', 'answered');

EXPLAIN SELECT * FROM orders
WHERE user_id = 5 ORDER BY created_at DESC LIMIT 5;

EXPLAIN SELECT COUNT(*) FROM enrollments WHERE course_id = 3;
```

در ستون `key` باید **نام ایندکس** (مثلاً `idx_tickets_user_status`) دیده شود.
اگر `key` خالی بود یعنی ایندکسی استفاده نشده — با پشتیبانی در میان بگذارید.

## مرحله ۶ — نگهداری دوره‌ای (یک‌بار در ماه)

```sql
-- بعد از ماه‌ها فعالیت، جداول را فشرده و آمار را به‌روز کنید (در ترافیک کم)
ANALYZE TABLE orders, notifications, enrollments, reviews;
OPTIMIZE TABLE orders, notifications, enrollments, reviews;
```

و اگر لاگ 404 خیلی بزرگ شد:

```sql
DELETE FROM notfound_logs WHERE last_seen < NOW() - INTERVAL 90 DAY;
OPTIMIZE TABLE notfound_logs;
```

## جمع‌بندی بردها

| کار | اثر |
|---|---|
| ایندکس‌های جدید (تیکت/سفارش/اعلان/...) | کوئری‌های پرتکرار از اسکن کامل → چند میلی‌ثانیه |
| `innodb_buffer_pool_size` | تکرار کوئری‌ها بدون لمس دیسک |
| `innodb_flush_log_at_trx_commit = 2` | نوشتن (سفارش/نظر/تیکت) چند برابر سریع‌تر |
| کاهش اتصال‌های MySQL پول | حذف خطاهای `Too many connections` (500) در هاست اشتراکی |
| پاک‌سازی لاگ 404 | کوچک‌شدن دیتابیس و بکاپ‌های سریع‌تر |
