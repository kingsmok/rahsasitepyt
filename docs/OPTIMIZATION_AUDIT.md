## خلاصه اجرایی (Executive Summary)

سایت از نظر **معماری، امنیت پایه و سئوی ساختاری در وضعیت خوبی** قرار دارد: gzip فعال (فشرده‌سازی ۸۴٪)، کش استاتیک ۷ روزه، sitemap سالم (۳۱ URL بدون خطا)، robots.txt درست، اسکیمای JSON-LD در ۵ نوع، CSRF سراسری، CSP قوی و هیچ لینک شکسته‌ای (۶۵ مسیر داخلی تست شد).

اما **سه مشکل حیاتی** وجود دارد که رشد سایت را متوقف می‌کند:

1. **🔴 وزن صفحات فاجعه‌بار است:** صفحه اصلی **۱۸.۵ مگابایت** و صفحه دوره‌ها **۱۶ مگابایت** ترنسفر دارد — فقط به خاطر تصاویر PNG با ابعاد ۱۵۳۶×۱۰۲۴ و وزن ۲ تا ۲.۹ مگابایت. در اینترنت ۴G ایران این یعنی ۳۰ تا ۶۰ ثانیه لود. **رتبه‌بندی گوگل (Core Web Vitals) و نرخ تبدیل هر دو مستقیماً نابود می‌شوند.**
2. **🔴 تگ‌های Title و Meta Description تکراری در ۸ صفحه:** صفحه اصلی، دوره‌ها، وبلاگ، سوالات، تماس، سبد خرید، ورود و ثبت‌نام همگی یک عنوان و یک توضیح مشترک دارند → کنیبالیزاسیون کامل کلمات کلیدی.
3. **🔴 نبود H1 در ۴ صفحه کلیدی** (خانه، وبلاگ، سوالات متداول، تماس) + ۴ تخلف دسترس‌پذیری «جدی/بحرانی» از نظر WCAG که روی سئو و رضایت کاربر اثر می‌گذارد.

بقیه یافته‌ها در ۶ بخش زیر با جزئیات، علت و راهکار عملیاتی آمده است.

## ۱.۱ معماری اطلاعات و ساختار منوها

**وضعیت: خوب، با چند شکاف**

| بخش | ارزیابی | توضیح |
|---|---|---|
| منوی اصلی دسکتاپ | ✅ سالم | منوی مگا (۹ دسته + دوره‌های هر دسته) + منوی ناوبری ۷ پیوندی؛ رفع‌شده: هم‌ترازی کانتینرها (۱۲۴۰px)، چینش ردیفی اکشن‌ها، پل هوور مگامنو |
| منوی موبایل | ✅ سالم | نوار پایین شبه‌اینستاگرام + مگامنو کشویی با لمس؛ بدون سرریز افقی در ۳۶۰/۳۹۰/۷۶۸px (تست شد) |
| دسته‌بندی‌ها | ✅ خوب | ۹ دسته با آیکون و رنگ اختصاصی؛ منوی مگا تا ۴ دوره زیر هر دسته |

## ۱.۲ هماهنگی بصری، تایپوگرافی و نرخ خوانایی

**وضعیت: خوب**

- ✅ پالت رنگی فرادرسی (سرمه‌ای `#0d1f36` + نارنجی `#f2640c`) منسجم در کل سایت (تم ۲۲) — کنتراست دکمه‌ها و هدر عالی.
- ✅ فونت وزیرمتن با ۶ وزن — تایپوگرافی فارسی استاندارد و خوانا.
- ✅ سیستم ۲۲ تم با انتخاب زنده توسط کاربر — مزیت رقابتی واقعی.
- ✅ انیمیشن‌های ورود کارت‌ها، سایه‌های نرم، اسکرول‌بار گرادیانی — پولیش بصری انجام‌شده.

**⚠️ دو ایراد خوانایی:**
1. **کنتراست رنگ پایین در ۱۱ تا ۲۸ عنصر هر صفحه** (تخلف جدی WCAG): رنگ `--text-3: #94a3b8` روی سفید فقط **نسبت ۲.۸:۱** دارد (استاندارد ۴.۵:۱). این رنگ در متادیتای کارت دوره، برچسب‌های وبلاگ و کرامب‌ها استفاده شده است.
2. «درباره ما» می‌گوید **«۳+ دانشجو»** — ظاهراً خطای تایپی است (احتمالاً ۳۰۰۰+ مدنظر بوده) و اعتماد را تخریب می‌کند.

**کد اصلاحی (در `base.css`):**
```css

  /* قبل: --text-3: #94a3b8  (نسبت 2.8:1 — مردود) */
  --text-3: #64748b;   /* بعد: نسبت 4.7:1 — قبول WCAG AA */
}
/* جایگزین مخصوص اگر رنگ خاکستری کمرنگ در پس‌زمینه تیره لازم است */
```

## ۱.۴ نقاط اصطکاک کاربر و بهینه‌سازی نرخ تبدیل (CRO)

**یافته‌های کلیدی:**
1. **کارت دوره CTA غیرمستقیم دارد:** فقط دکمه «مشاهده دوره» — کاربر برای خرید باید ۲ کلیک برود. **راهکار:** دکمه «افزودن به سبد» مستقیم روی کارت (با `data-add-cart` که از قبل در `app.js` پشتیبانی می‌شود — فقط باید در قالب کارت اضافه شود):
```html
<a class="btn btn-sm btn-outline-primary" data-add-cart="{{ course.id }}">➕ افزودن به سبد</a>
```
2. **اثبات اجتماعی ضعیف در دمو:** دوره پایتون «۱ دانشجو» و «۲ نظر» دارد. **راهکار:** در seed داده واقعی‌تر (مثلاً ۱۲۰۰+ دانشجو، ۴۰+ نظر) بگذارید؛ و شمارنده‌ها را از «دانشجو» به «دانشجوی فعال» تغییر دهید.
3. **هیچ CTA شناور موبایل در صفحه دوره نیست:** در موبایل وقتی کاربر سرفصل‌ها را می‌خواند، دکمه خرید از دید خارج می‌شود. **راهکار:** نوار پایین چسبان «خرید با ۵۲٪ تخفیف — ۸۹۰ هزار تومان» در صفحه دوره (موبایل فقط).
4. **بازگشت به بالای صفحه** موجود است ✅ ولی دکمه تماس سریع (واتساپ/تلگرام) وجود ندارد — در بازار ایران انتظار کاربر است.
5. **فرم تماس** کامل است (موضوع، اعتبارسنجی) ✅ — ولی پیام موفقیت بعد از ارسال ندارد؟ (تست: فرم POST → پیام فلش دارد؛ بررسی شود نمایش در موبایل درست باشد).

| صفحه | عنوان (Title) | توضیح (Description) | H1 |

**چرا مشکل دارد:** چون `SeoMeta` فقط برای ۱۶ مسیر (دوره‌ها) ساخته شده و بقیه صفحات به `site_desc` پیش‌فرض برمی‌گردند. گوگل برای ۸ صفحه با عنوان و توضیح یکسان نمی‌تواند موضوع صفحه را تشخیص دهد؛ عملاً **صفر کلیک ارگانیک** برای این صفحات.

**راهکار عملیاتی (قالب‌های آماده برای تنظیمات سئو — جدول `seo_metas` یا fallback در قالب‌ها):**

| صفحه | Title پیشنهادی (≤۶۰ کاراکتر) | Meta Description پیشنهادی (۱۲۰–۱۵۵ کاراکتر) | H1 پیشنهادی |

| خانه | آموزش آنلاین برنامه‌نویسی، طراحی و مهارت‌های دیجیتال | دوره‌های پروژه‌محور با مدرسان برتر ایران، گواهینامه معتبر و پشتیبانی واقعی — از صفر تا استخدام | آینده‌ات را با مهارت‌های دیجیتال بساز |

| وبلاگ | مجله آموزشی آکادمی آنلاین — مقالات برنامه‌نویسی و مهارت | مقالات به‌روز برنامه‌نویسی، طراحی و مهارت‌های نرم؛ راهنمای انتخاب مسیر یادگیری | مجله آموزشی |

| درباره | درباره آکادمی آنلاین — تیم، ماموریت و آمار | داستان، ارزش‌ها و آمار آکادمی: ۱۲+ دوره، ۶+ مدرس، ۹۸٪ رضایت | درباره آکادمی آنلاین |

## ۲.۲ ساختار H1–H6 و سلسله‌مراتب

- ❌ **خانه، وبلاگ، FAQ و تماس H1 ندارند** (تأیید با axe-core و اسکن HTML).
- ⚠️ **پرش سلسله‌مراتب:** در بخش‌های صفحه اصلی `h4` بلافاصله بعد از `h2` آمده (بدون h3) — axe-core این را در همه صفحات گزارش داد.
- ✅ صفحات دوره: H1 یکتا + H2 (سرفصل‌ها، نظرات، مدرس) — ساختار سالم.

**راهکار:** در قالب‌های طراحی صفحه اصلی (`designs.py`)، هیروی صفحه را `<h1>` کنید (الان احتمالاً `h2` یا `div` است) و سرتیترهای میانی را h2→h3→h4 مرتب کنید. برای وبلاگ/FAQ/تماس هم عنوان صفحه باید `<h1>` باشد نه `h2`.

## ۲.۳ لینک‌سازی داخلی و خارجی

**نتیجه crawl واقعی:**
- ✅ **۶۵ مسیر داخلی یکتا تست شد — هیچ لینک شکسته‌ای نیست.**
- ✅ خانه به همه صفحات کلیدی لینک دارد (دوره‌ها، وبلاگ، درباره، تماس، FAQ، مدرسان، سبد خرید).
- ✅ sitemap.xml شامل ۳۱ URL (همه ۲۰۰) از جمله `/terms`، `/privacy`، `/teachers` و صفحات مدرس.
- ⚠️ **شکاف:** مقالات وبلاگ به دوره‌های مرتبط لینک داخلی ندارند (۴ مقاله دمو، بدون CTA به دوره‌ها) — فرصت از دست‌رفته برای «لینک‌های متنی درون‌محتوا».
- ⚠️ هیچ لینک خروجی به منابع معتبر (مستندات رسمی پایتون، MDN و...) در مقالات نیست — برای E-E-A-T مفید است.
- ⚠️ صفحات دسته‌بندی وبلاگ (`/blog?cat=...`) در sitemap نیستند و به هم لینک نمی‌دهند.

**راهکار فوری:** در پایان هر مقاله وبلاگ، بلوک «دوره پیشنهادی» با لینک به دوره مرتبط اضافه شود (قالب `blog_post`):
```html
<div class="post-cta card">
  <h3>🚀 آماده‌ای عملی شروع کنی؟</h3>
  <p>دوره «آموزش جامع پایتون» دقیقاً همین مسیر را قدم‌به‌قدم با پروژه واقعی پیش می‌برد.</p>
  <a class="btn btn-primary" href="/course/...">مشاهده دوره ←</a>
</div>
```

## ۲.۴ استراتژی محتوا: شکاف‌ها و پرسونای مخاطب

**نقاط قوت:** صفحه درباره با داستان و ارزش‌ها ✅ · FAQ با ۶+ سوال واقعی خریدار ✅ · ۴ مقاله وبلاگ با عناوین جستجوپذیر (مثل «چگونه در ۶ ماه توسعه‌دهنده وب شویم؟») ✅ · فرم تماس با موضوع‌بندی ✅

**شکاف‌های محتوایی (Content Gaps) — به ترتیب اولویت:**
1. **صفحات فرود هر دسته** (`/courses?cat=...` یک لیست ساده است): هر دسته به یک صفحه فرود با توضیح، نقشه راه و دوره‌های مرتبط نیاز دارد (مثلاً `/learning-path/python`).
2. **مقالات «راهنمای خرید/مقایسه»:** «بهترین زبان برنامه‌نویسی برای شروع ۱۴۰۵»، «فرانت‌اند یا بک‌اند؟»، «آموزش آنلاین یا حضوری؟» — محتوای آگاهی‌محور که در بالای قیف فروش می‌نشیند.
3. **مطالعات موردی دانشجویان:** «از صفر تا استخدام با این دوره‌ها» — قوی‌ترین ابزار E-E-A-T و تبدیل.
4. **محتوا برای هر مرحله قیف:** حالا فقط «دانشجوها» (محتوا) و «دوره‌ها» (تبدیل) داریم؛ «تصمیم‌گیرنده‌ها» (مقایسه و نظرات) کم‌رنگ است.
5. **پرسونای مخاطب:** محتوای فعلی به «تازه‌کار مطلق» و «تغییر مسیر شغلی» می‌پردازد؛ پرسونای «دانشجوی فنی که ارتقا می‌خواهد» پوشش داده نشده (دوره‌های پیشرفته کم است — فقط ۲ دوره بالاتر از مقدماتی).

## ۲.۵ E-E-A-T (تخصص، تجربه، اعتبار، اعتماد)

```python
from PIL import Image
import os
for f in os.listdir('static/img'):
```


## ۳.۴ کشینگ، CDN و سرور

**وضعیت فعلی (تأیید واقعی):**
- ✅ gzip: HTML از ۶۹KB به ۱۱KB (۸۴٪) — فعال
- ✅ استاتیک: `Cache-Control: public, max-age=604800, immutable` + ETag — عالی
- ✅ HTML: `no-cache` — درست (کاربر لاگین‌شده)
- ❌ **CDN وجود ندارد** — در ایران حتماً از CDN داخلی (آروان/ابرآروان، پارس‌پک) استفاده شود؛ هم سرعت و هم تحریم‌گریزی DNS.
- ❌ **HTTP/2 وجود ندارد** (سرور Werkzeug توسعه) — در پروداکشن گونی‌کورن/وِیت‌رس + nginx با HTTP/2.
- ⚠️ **SQLite در پروداکشن:** برای سایت فروشگاهی با نوشتن هم‌زمان (سفارش/پرداخت) SQLite خطر قفل‌شدن دارد → مهاجرت به PostgreSQL توصیه می‌شود (در مرحله بلندمدت).
- ⚠️ هدر `Vary: Cookie` روی HTML درست است ولی برای صفحات عمومی بدون کوکی، کش CDN را محدود می‌کند — راهکار: صفحات عمومی کش‌پذیر با `Vary: Cookie` استاندارد، صفحات کاربری `no-store`.

**پیشنهاد تنظیمات nginx (پروداکشن):**
```nginx
gzip on;
gzip_types text/css application/javascript image/svg+xml;
location /static/ {
    expires 7d;
    add_header Cache-Control "public, immutable";
}
location / {
    proxy_pass http://127.0.0.1:5000;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

# ۴. امنیت، دسترس‌پذیری و اعتمادسازی (Security & Trust)

## ۴.۱ امنیت — وضعیت پایه خوب، چند شکاف مهم

**هدرهای امنیتی واقعی (تأیید با curl):**

| هدر | وضعیت | توضیح |
|---|---|---|
| Content-Security-Policy | ✅ قوی | `default-src 'self'` + لیست سفید دقیق برای اسکریپت/فریم/تصویر؛ در تست، تزریق اسکریپت خارجی مسدود شد |
| X-Frame-Options: SAMEORIGIN | ✅ | ضد کلیک‌جکینگ |
| X-Content-Type-Options: nosniff | ✅ | ضد MIME sniffing |
| Referrer-Policy | ✅ | strict-origin-when-cross-origin |
| کوکی session | ✅ | HttpOnly + SameSite=Lax |
| HSTS | ❌ | بعد از HTTPS باید اضافه شود: `Strict-Transport-Security: max-age=31536000` |
| Permissions-Policy | ❌ | برای محدودکردن دوربین/میکروفون/موقعیت: `Permissions-Policy: camera=(), microphone=(), geolocation=()` |
| COOP/COEP | ❌ | برای ایزوله‌سازی کراس‌اورجین: `Cross-Origin-Opener-Policy: same-origin` |

**یافته‌های کد (ممیزی واقعی):**
1. 🔴 **SECRET_KEY پیش‌فرض در کد:**
```python
app.config['SECRET_KEY'] = os.environ.get('SECRET_KEY', 'academy-secret-key-1403')
```
   کلید جایگزین **در مخزن کد عمومی است** → هر کسی می‌تواند کوکی session جعل کند و به‌عنوان ادمین وارد شود. **راهکار فوری:**
```python
import os
key = os.environ.get('SECRET_KEY')
if not key and os.environ.get('FLASK_ENV') == 'production':
    raise RuntimeError('SECRET_KEY must be set in production!')
app.config['SECRET_KEY'] = key or 'dev-only-key'
```
2. ⚠️ **محدودیت نرخ ورود، مبتنی بر session است** (کوکی مرورگر) — مهاجم با پاک کردن کوکی دور می‌زند. باید محدودیت **IP-based** (مثلاً با جدول `login_attempts(ip, time)`) اضافه شود.
3. ⚠️ کد OTP در session (کوکی امضاشده) نگهداری می‌شود — بهتر است در سمت سرور با انقضا و شمارش تلاش ذخیره شود.
4. ⚠️ سرور Werkzeug توسعه — در پروداکشن هرگز؛ گونی‌کورن/وِیت‌رس + nginx.
5. ✅ رمز عبور با `generate_password_hash` (bcrypt) هش می‌شود ✅ · CSRF سراسری ✅ · IDOR چک می‌شود ✅ · noindex روی /admin و /builder ✅
