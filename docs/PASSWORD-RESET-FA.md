# 🔑 رمز عبور را در دیتابیس عوض کردم ولی تغییر نمی‌کند — راهنمای کامل

اگر در phpMyAdmin (یا هر ابزار دیتابیس) ستون `password_hash` را دست‌کاری کردید و
باز هم رمز جدید کار نکرد، یکی از ۵ دلیل زیر است. به ترتیب چک کنید.

---

## ✅ سریع‌ترین راه‌حل (توصیه‌شده) — اصلاً به دیتابیس دست نزنید

روی هاست، در پوشه پروژه این دستور را بزنید:

```bash
python3 scripts/set_password.py --email admin@site.ir --password 'رمزجدید123'
```

روی هاست اشتراکی (cPanel) معمولاً باید پایتون venv را صدا بزنید:

```bash
./venv/bin/python scripts/set_password.py --email admin@site.ir --password 'رمزجدید123'
# یا
/home/USER/virtualenv/public_html/class/3.11/bin/python scripts/set_password.py --email admin@site.ir --password 'رمزجدید123'
```

این اسکریپت:
- دقیقاً به **همان دیتابیسی که سایت استفاده می‌کند** وصل می‌شود (و آدرسش را چاپ می‌کند)
- رمز را با هش قوی (scrypt) ذخیره می‌کند
- سشن‌های باز قبلی کاربر را باطل می‌کند
- اگر حساب غیرفعال باشد فعالش می‌کند
- در پایان خودش تست می‌کند که رمز واقعاً کار می‌کند

دستورهای مفید دیگر:

```bash
# دیدن همه کاربران و اینکه رمزشان چه نوع هشی دارد
python3 scripts/set_password.py --list

# تست اینکه یک رمز درست است یا نه (بدون تغییر)
python3 scripts/set_password.py --email admin@site.ir --check 'رمزی-که-فکر-می‌کنید'

# با شناسه یا موبایل
python3 scripts/set_password.py --id 5 --password 'رمزجدید123'
python3 scripts/set_password.py --phone 09120000000 --password 'رمزجدید123'
```

## دلیل ۱ (شایع‌ترین) — سایت اصلاً به آن دیتابیس وصل نیست

اگر `DATABASE_URL` در فایل `.env` **خالی** باشد، سایت از SQLite محلی
(`instance/academy.db`) استفاده می‌کند — نه از MySQL. یعنی هرچه در phpMyAdmin
عوض کنید هیچ اثری ندارد، چون سایت آن جدول را اصلاً نمی‌خواند.

**بررسی:**

```bash
python3 scripts/set_password.py --list
```

خط اول خروجی، آدرس دیتابیس واقعی سایت را نشان می‌دهد. اگر `sqlite:///...` دیدید
ولی انتظار MySQL داشتید، `.env` را درست کنید:

```env
DATABASE_URL=mysql+pymysql://USER:PASS@localhost:3306/DBNAME?charset=utf8mb4
```

اگر فهرست کاربران خالی بود یا کاربر شما آنجا نبود → قطعاً دیتابیس اشتباه است.

عیب‌یابی کامل اتصال: `python3 scripts/diagnose_db.py`

## دلیل ۲ — رمز را «متن ساده» نوشته‌اید

اگر در phpMyAdmin بنویسید:

```sql
UPDATE users SET password_hash = 'mypassword123' WHERE id = 1;   -- ❌ کار نمی‌کند
```

سایت این را قبول نمی‌کند، چون انتظار هش دارد نه متن خام (و این از نظر امنیتی هم درست است).

**سه راه درست از داخل phpMyAdmin:**

```sql
-- ۱) با پیشوند plain: — ساده‌ترین راه
UPDATE users SET password_hash = 'plain:رمزجدید123' WHERE id = 1;

-- ۲) با MD5 (پشتیبانی قدیمی)
UPDATE users SET password_hash = MD5('رمزجدید123') WHERE id = 1;

-- ۳) با SHA1 یا SHA256
UPDATE users SET password_hash = SHA1('رمزجدید123') WHERE id = 1;
UPDATE users SET password_hash = SHA2('رمزجدید123', 256) WHERE id = 1;
```

در هر سه حالت، کاربر با همان رمز وارد می‌شود و سیستم **در همان ورود اول** خودکار
رمز را به هش قوی (scrypt) تبدیل می‌کند. یعنی متن ساده در دیتابیس نمی‌ماند.

> ⚠️ بعد از `UPDATE` حتماً روی دکمه‌ی اجرا/Go بزنید و مطمئن شوید پیام
> «۱ ردیف تغییر کرد» آمده. اگر «۰ ردیف» گفت، شرط `WHERE` شما به هیچ کاربری نخورده.

---

## دلیل ۳ — سشن قدیمی هنوز باز است

اگر با همان مرورگر لاگین بوده‌اید، کوکی سشن قدیمی هنوز معتبر است و حس می‌کنید
«رمز عوض نشده». راه‌حل:

- یک بار **خروج** بزنید، یا
- پنجره ناشناس (Incognito) باز کنید، یا
- از اسکریپت `set_password.py` استفاده کنید (خودش سشن‌ها را باطل می‌کند)

از داخل phpMyAdmin هم می‌شود همه سشن‌ها را باطل کرد:

```sql
UPDATE users SET session_token = NULL WHERE id = 1;
```

## دلیل ۴ — سرور ری‌استارت نشده

روی هاست‌های Passenger/cPanel، کد و بعضی داده‌ها در حافظه ورکر می‌مانند:

```bash
touch passenger_wsgi.py
```

یا از پنل هاست: Python App → **Restart**.

---

## دلیل ۵ — حساب غیرفعال است یا ایمیل فرق دارد

- اگر `is_active = 0` باشد، پیام «ایمیل یا رمز عبور اشتباه است» می‌بینید حتی با رمز درست
  (این عمدی است تا وجود حساب لو نرود).
- ایمیل هنگام ورود **کوچک** (lowercase) می‌شود؛ اگر در دیتابیس با حروف بزرگ ذخیره شده
  باشد، کاربر پیدا نمی‌شود.

```sql
UPDATE users SET is_active = 1, email = LOWER(email) WHERE id = 1;
```

---

## ℹ️ نکته درباره ورود مدیر (2FA)

حساب‌های `admin` و `super_admin` بعد از ورود، مرحله **تایید دومرحله‌ای** دارند و
کد به موبایل کاربر پیامک می‌شود. اگر پیامک تنظیم نشده باشد، کد به‌صورت پیام روی
همان صفحه نمایش داده می‌شود. مطمئن شوید شماره موبایل ادمین در دیتابیس درست است.

---

## 🔒 غیرفعال‌کردن پذیرش هش‌های قدیمی

بعد از اینکه همه رمزها ارتقا یافتند، می‌توانید پشتیبانی قدیمی را ببندید — در `.env`:

```env
LEGACY_MD5=0
LEGACY_PLAIN=0
```

از آن به بعد فقط هش‌های قوی پذیرفته می‌شوند و تغییر رمز فقط از پنل ادمین یا
`scripts/set_password.py` ممکن است.

---

## خلاصه در یک جدول

| علامت | علت | راه‌حل |
|---|---|---|
| فهرست کاربران خالی/متفاوت | دیتابیس اشتباه | `DATABASE_URL` در `.env` |
| رمز جدید کار نمی‌کند | متن ساده نوشته‌اید | `'plain:رمز'` یا `MD5('رمز')` |
| هنوز لاگین‌ام | سشن قدیمی | خروج / `session_token = NULL` |
| هیچ تغییری دیده نمی‌شود | ری‌استارت نشده | `touch passenger_wsgi.py` |
| «ایمیل یا رمز اشتباه» با رمز درست | حساب غیرفعال | `is_active = 1` |
