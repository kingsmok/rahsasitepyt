# 🎨 مشخصات کامل طراحی محصول — آکادمی آنلاین (LMS فارسی)

> **سند مرجع واحد UX/UI / Design System / Frontend**
> محصول: پلتفرم آموزش آنلاین و فروشگاه دوره (Flask + صفحه‌ساز داخلی)
> زبان و جهت: فارسی (RTL) — با پشتیبانی LTR برای فیلدهای فنی (ایمیل/کد/شماره)
> پلتفرم: Responsive Web (Desktop-first، موبایل‌بهینه) — توزیع سورس Python
> وضعیت: سند تصمیم‌محور؛ جایگزین پراکندگی مستندات قبلی. هر تصمیم این سند با توکن‌های CSS موجود (`base.css` + `theme-23.css` + `ux.css`) قابل پیاده‌سازی است.

# ۰) خلاصه تصمیمات و مفروضات کلیدی

از آنجا که فیلدهای «نام محصول / نوع / هدف / مخاطب / پلتفرم» در دستور کار خالی بودند، بر اساس تحلیل واقعیِ کد و مستندات مخزن، این مفروضات قطعی و مبنای همه‌ی طراحی‌ها قرار گرفت:

| مورد | تصمیم اتخاذشده | دلیل |
|---|---|---|
| **نام محصول** | «آکادمی آنلاین» (Brand قابل تغییر از «تنظیمات ← برند») | نام‌گذاری موجود؛ برند یک توکن متنی است نه هویت سخت‌کدشده |
| **نوع محصول** | پلتفرم SaaS/وب — LMS + فروشگاه دوره + انجمن + آزمون + گواهی | مطابق امکانات واقعی محصول |
| **هدف اصلی** | فروش و ارائه دوره‌های آنلاین، هدایت یادگیری، صدور گواهی معتبر و حفظ کاربر بازگشتی | هدف تجاری + آموزشی توأمان |
| **مخاطب** | دانشجو (۱۸–۴۵)، مدرس، مدیر/اپراتور، خریدار سازمانی | نقش‌های واقعی `Permission` در کد |
| **زبان/جهت** | فارسی RTL؛ اعداد فارسی؛ LTR فقط برای ایمیل/کد/شماره (`dir=ltr`) | استاندارد محصول فارسی |
| **سبک بصری** | مدرن، مینیمال، توکن‌محور، «فیروزه» (theme-23) به‌عنوان تم مرجع | هم‌خوان با تصمیم قبلی «مسیر الف: فیروزه» |
| **اصل معماری** | «همه‌چیز تم + صفحه‌ساز» — هیچ المانی بدون وضعیت مشخص حذف/سخت‌کد نمی‌شود | قانون موجود محصول |
| **مبنا** | کاهش مراحل، یک CTA اصلی در هر صفحه، خطاهای inline، لمس ≥ 44px، WCAG AA | دستور کار داده‌شده |

**سه اصل راهنمای کل طراحی (تصمیم‌گیری در ابهام):**
1. **وضوح بر تزئین** — اگر انتخابی بین دو راه‌حل بود، ساده‌تر/سریع‌تر/قابل‌توسعه‌تر انتخاب می‌شود.
2. **یک هدف، یک CTA** — هر صفحه یک هدف دارد و CTA اصلی آن همیشه از لحاظ بصری متمایزترین عنصر است.
3. **خطا = مشکل + راه‌حل** — هیچ پیام خطایی بدون ارائه‌ی گام بعدی نمایش داده نمی‌شود.

# ۱) تحلیل محصول

## ۱.۱ هدف و ارزش
محصول سه ارزش اصلی را هم‌زمان ارائه می‌دهد:
- **برای دانشجو:** مسیر یادگیری واضح، خرید امن، پخش ویدیو با محافظت (واترمارک)، گواهی قابل استعلام.
- **برای مدرس:** فروش دوره، داشبورد درآمد/دانشجو/نمره‌دهی.
- **برای مالک:** فروش، سئو، گزارش، لایسنس و مدیریت محتوا بدون وابستگی به توسعه‌دهنده (صفحه‌ساز).

## ۱.۲ مهم‌ترین مشکلات کاربران (مبنای تصمیمات UX)
| # | مشکل کاربر | پاسخ طراحی |
|---|---|---|
| ۱ | **گیج‌شدن بین «ورود» و «ثبت‌نام»** | ورود/ثبت‌نام با شماره تماس یکپارچه شد (یک فرم؛ اگر شماره جدید بود خودکار ثبت‌نام می‌شود) — کاهش از ۲ فرم به ۱ مسیر |
| ۲ | **پیدا نکردن CTA خرید در موبایل** | نوار خرید چسبان پایین + دکمه اصلی همیشه در دسترس شست |
| ۳ | **خطای فرم بدون مشخص‌بودن محل** | اعتبارسنجی inline فیلدبه‌فیلد + اسکرول خودکار به اولین خطا |
| ۴ | **ترس از پرداخت** | مراحل کم، پیش‌نمایش سفارش، برچسب «پرداخت امن»، نمادهای اعتماد |
| ۵ | **پیدا نکردن «ادامه یادگیری»** | داشبورد کارمحور: بزرگ‌ترین بلوک = «ادامه یادگیری» |
| ۶ | **اعتماد به گواهی** | کد رهگیری یکتا + صفحه استعلام عمومی |
| ۷ | **سردرگمی در پنل ادمین** | منوی گروه‌بندی‌شده ۸ بخشی + داشبورد متراکم |
| ۸ | **جدول‌های ناخوانا در موبایل** | تبدیل جدول → کارت در موبایل |

## ۱.۳ ساختار منطقی و اولویت قابلیت‌ها
اولویت بر اساس نرخ تبدیل و ارزش:
1. **مسیر خرید/ثبت‌نام دوره** (بیشترین ارزش تجاری)
2. **تجربه یادگیری** (پخش، پیشرفت، گواهی — حفظ کاربر)
3. **پنل‌ها** (دانشجو/مدرس/ادمین — عملیات روزانه)
4. **محتوای عمومی** (وبلاگ، سئو، درباره/تماس — جذب)

# ۲) پرسونای کاربران

## پرسونای ۱ — «سارا»، دانشجوی مهارت‌محور
- **مشخصات:** ۲۶ ساله، کارمند، دنبال ارتقای شغلی، تلفن‌همراه اولویت اصلی، آشنایی متوسط با فناوری.
- **نیاز:** دوره‌ی پروژه‌محور با گواهی معتبر، خرید سریع و امن، یادگیری در زمان‌های مرده (موبایل).
- **درد:** ترس از پرداخت آنلاین، فراموشی رمز، پیدا نکردن ادامه‌ی درس.
- **معیار موفقیت:** «از لحظه ورود به صفحه دوره تا شروع درس اول کمتر از ۳ دقیقه».

## پرسونای ۲ — «امیر»، مدرس/تولیدکننده محتوا
- **مشخصات:** ۳۴ ساله، دوره‌ساز، روزانه پنل را چک می‌کند.
- **نیاز:** دیدن فروش/دانشجو، پاسخ به پرسش‌ها، نمره‌دهی، مدیریت جلسات.
- **درد:** پیمایش زیاد بین صفحات.
- **معیار موفقیت:** «همه‌ی عملیات روزانه از یک داشبورد متراکم، در کمتر از ۲ کلیک».

## پرسونای ۳ — «رضا»، مدیر/اپراتور آکادمی
- **مشخصات:** ۳۸ ساله، غیرفنی، مسئول فروش/محتوا/پشتیبانی.
- **نیاز:** مدیریت دوره/سفارش/کوپن/کاربران و گزارش، بدون کدنویسی.
- **درد:** پیچیدگی پنل، ترس از خطای غیرقابل‌بازگشت.
- **معیار موفقیت:** «هر عمل مخرب، تأیید صریح و قابل بازگشت دارد».

## پرسونای ۴ — «محمد»، خریدار سازمانی (B2B)
- **مشخصات:** مسئول آموزش شرکت، خرید انبوه/قسطی (BNPL).
- **نیاز:** فاکتور رسمی، خرید چند صندلی، پرداخت اقساطی.
- **معیار موفقیت:** «فاکتور فارسی قابل چاپ + رهگیری سفارش».

# ۴) User Flowهای اصلی

## ۴.۱ ثبت‌نام / ورود با OTP (یک مسیر واحد)
```
ورود → شماره تماس → [کاربر جدید؟] 
   ├─ بله → ثبت خودکار + کد ملی (اختیاری) → تکمیل پروفایل → داشبورد
   └─ نه  → کد OTP → ورود → (کد ملی اگر ناقص) → داشبورد
```
**قوانین:** ارسال مجدد کد با شمارنده‌ی ۶۰ ثانیه · حداکثر ۵ بار در ۱۰ دقیقه · «مرا به خاطر بسپار» (۳۰ روز) · 2FA برای ادمین.

## ۴.۲ خرید و پرداخت (کمترین مرحله ممکن)
```
جزئیات دوره → [ثبت‌نام در دوره] → سبد (پیش‌نمایش) → تسویه 
   → کد تخفیف (اختیاری) → روش پرداخت → درگاه → بازگشت → نتیجه (موفق/ناموفق)
```
**کاهش مرحله:** دکمه «ثبت‌نام» مستقیماً به سبد می‌رود (بدون صفحه واسطه)؛ تسویه یک‌صفحه‌ای است (آدرس/کوپن/روش پرداخت در یک فرم).

## ۴.۳ فراموشی رمز عبور
```
فراموشی رمز → شماره تماس → کد OTP → رمز جدید → موفقیت → ورود
```

## ۴.۴ یادگیری
```
داشبورد → «ادامه یادگیری» → پلیر + فهرست جلسات → تکمیل جلسه → پیشرفت ↑ → جلسه بعد
```

## ۴.۵ ایجاد/ویرایش محتوا (مدرس/ادمین)
```
پنل → «دوره جدید» → فرم چندبخشی (اطلاعات → جلسات → قیمت/انتشار) → پیش‌نمایش → انتشار
```

# ۷) طراحی نهایی UI (سطح صفحه)

> اصول بصری: مینیمال، سایه فقط برای لایه‌های شناور، گوشه‌ها حداکثر ۱۶px (کارت) و ۱۰px (دکمه)، فاصله‌گذاری بر پایه ۸px، یک رنگ برند غالب + رنگ‌های وضعیت کم‌مصرف.

- **هدر:** پس‌زمینه شیشه‌ای (blur)، در اسکرول سایه ظریف. جستجو بزرگترین عنصر تعاملی بعد از لوگو.
- **کارت دوره:** تصویر 16:9 → بج تخفیف/وضعیت → دسته → عنوان (۲ خط) → مدرس → امتیاز → قیمت (خط‌خورده + اصلی) → **یک دکمه CTA مشخص** + دکمه علاقه‌مندی (آیکون، ثانویه).
- **پلیر:** فهرست جلسات در کنار (راست در RTL)، نوار پیشرفت، واترمارک نام/کد ملی، دکمه تکمیل جلسه.
- **پنل‌ها:** نوار کناری راست (RTL) با منوی گروه‌بندی‌شده، محتوا در سمت چپ؛ جدول → کارت در موبایل.
- **صفحه‌ساز:** بوم داخل iframe، پالت راست، پنل تنظیمات سه‌تبه (محتوا/استایل/پیشرفته)، تولبار بالا با undo/redo/ذخیره/دستگاه‌ها.

# ۹) کامپوننت‌ها، Variants و وضعیت‌ها

## ۹.۱ دکمه
- **Variants:** Primary · Secondary (outline) · Ghost · Accent · Danger · Success · White · Text/Link.
- **Sizes:** `sm` (32px) · `md` (42px) · `lg` (48px) · `block`.
- **وضعیت‌ها:** Default · Hover (روشن‌تر + translateY(-2px) + سایه) · Pressed (`translateY(0)` + سایه کمتر) · Focus (outline 3px برند) · Disabled (opacity .55 + no pointer) · Loading (اسپینر + غیرفعال + متن ثابت می‌ماند).

## ۹.۲ فیلد ورودی (Input/Select/Textarea)
- **وضعیت‌ها:** Default (border 1.5px) · Focus (border برند + ring 4px `--primary-soft`) · Error (border danger + پیام inline + آیکون ⚠) · Success (border success) · Disabled (opacity .68 + `not-allowed`) · Readonly.
- **اجزا:** label (با `*` الزامی) · hint راهنما · placeholder · آیکون پیشوند/پسوند · toggle نمایش رمز · شمارنده قدرت رمز.

## ۹.۳ انتخابگرها
- **Checkbox / Radio:** `accent-color` برند، برچسب قابل کلیک، در `:has(:checked)` برجسته.
- **Switch:** توگل 2 حالته با برچسب معنادار و state واضح (نه فقط رنگ).
- **Select:** بومی با `appearance` کنترل‌شده، placeholder معنادار.

## ۹.۴ Tabs
خط زیرین + state فعال با رنگ برند؛ کیبورد-دوست (جهت‌نما برای جابه‌جایی).

## ۹.۵ Modal
پس‌زمینه تیره blur، فوکوس اولیه و trap، دکمه بستن (Esc)، عنوان واضح، دو دکمه عمل. **تأیید حذف** همیشه: عنوان = عمل، متن = پیامد (غیرقابل بازگشت)، دکمه‌ها = «حذف» (danger) / «انصراف».

## ۹.۶ Tooltip
فقط برای اطلاعات تکمیلی، نه جایگزین برچسب؛ نمایش با hover/focus.

## ۹.۷ Toast
گوشه پایین-راست (RTL)، آیکون وضعیت + متن + دکمه بستن، `role=status`/`role=alert`، ماندگاری ۴s (خطا ۶s).

## ۹.۸ Table
هدر `--n-100` چسبان، خطوط جداکننده ظریف، سطر focus-visible؛ **موبایل → کارت**.

## ۹.۹ Card / Badge / Pagination / Navigation
- **Card:** radius 14، border نازک به‌جای سایه سنگین، هاور سایه متوسط + بالا آمدن.
- **Badge:** radius-full، پس‌زمینه soft، متن 12px، همیشه آیکون/متن.
- **Pagination:** لینک‌های لمسی ≥ 40px، صفحه فعلی برجسته، «قبلی/بعدی».
- **Navigation:** آیتم فعال با رنگ برند + نشانگر؛ منوی موبایل = Bottom Nav با دایره فعال.

## ۹.۱۰ Icon
سبک خطی یکدست، `aria-hidden` + برچسب متنی/`aria-label`، stroke یکسان، رنگ از توکن.

## ۹.۱۱ Skeleton / Loader / Empty / Error / Offline
- **Skeleton:** شِمِر `--n-100` مطابق چیدمان محتوای واقعی (کارت/خط/دکمه).
- **Empty:** آیکون ملایم + عنوان + یک خط راهنما + **CTA شروع**.
- **Error:** «چه شد + چرا + چه کنم» + دکمه تلاش مجدد.
- **Offline:** بنر/صفحه با وضعیت اتصال + «تلاش مجدد».

# ۱۲) قوانین تعامل و رفتار

1. **فوکوس:** همه‌ی عناصر تعاملی `focus-visible` با outline برند (3px، offset 2px)؛ ترتیب تب منطقی.
2. **بازخورد:** هر عمل کاربر → بازخورد فوری (Toast/Inline/اسپینر) در < 300ms درک‌شده.
3. **جلوگیری از خطا:** دکمه‌های مخرب غیرفعال تا تکمیل پیش‌نیاز؛ تأیید صریح برای حذف.
4. **حالت‌ها:** هیچ صفحه‌ای بدون Empty/Loading/Error/Success کامل نمی‌شود.
5. **حرکت:** انیمیشن‌ها 150–300ms، قابل کاهش با `prefers-reduced-motion`.
6. **فرم:** اعتبارسنجی لحظه‌ای (on blur)، اسکرول به اولین خطا، پیام inline، شمارنده ارسال OTP.
7. **ثبات:** CTA اصلی در همه‌ی صفحات یک سبک (primary)؛ CTA ثانویه outline/ghost.
8. **مسیر کوتاه:** حذف هر مرحله‌ی غیرضروری؛ پیش‌پرکردن داده‌های شناخته‌شده.

# ۱۳) دسترسی‌پذیری (WCAG 2.1 AA)

- کنتراست متن ≥ 4.5:1 (متن عادی) و ≥ 3:1 (متن بزرگ/UI) — همه توکن‌ها تست‌شده.
- رنگ تنها رسانه‌ی معنا نیست (آیکون + متن همراه خطا/موفقیت).
- ساختار Heading منطقی (یک H1 در هر صفحه، سپس H2/H3).
- تصاویر `alt` معنادار؛ آیکون‌ها `aria-hidden` + برچسب.
- فوکوس قابل مشاهده + ترتیب تب + skip-link به محتوا.
- فرم‌ها با `label`/`aria-describedby` برای hint و خطا؛ `aria-invalid` در خطا.
- Toast/Modal با `role` مناسب و مدیریت فوکوس.
- `prefers-reduced-motion` رعایت شود؛ اندازه فونت قابل بزرگ‌نمایی (rem).
- اهداف لمسی ≥ 44×44px.

# ۱۴) راهنمای پیاده‌سازی برای توسعه‌دهنده

> فایل‌های مرتبط: `static/css/base.css` (توکن پایه) · `static/css/themes/theme-23.css` (تم مرجع) · `static/css/ux.css` (لایه UX) · `templates/base.html` · `templates/partials/*` · `design_variants.py` · `persian_palettes.py`.

1. **هرگز رنگ/سایه/گوشه را در قالب hardcode نکنید** — فقط از `var(--...)` استفاده کنید؛ تعویض تم = تعویض هویت بدون کدنویسی.
2. **سایه‌ها:** برای سایه‌ی رنگی از `color-mix(in srgb, var(--primary) X%, transparent)` استفاده کنید تا با هر تم هماهنگ بماند (الگوی موجود).
3. **کنتراست دکمه:** از توکن‌های `--on-primary` / `--on-accent` برای رنگ متن روی دکمه استفاده کنید (برای تم‌های روشن، متن تیره می‌شود).
4. **RTL:** همه‌چیز راست‌چین؛ فیلدهای فنی (ایمیل/کد/شماره) `dir=ltr`. از `margin-inline`/`padding-inline` به‌جای `left/right` استفاده کنید.
5. **اعداد:** در متن فارسی از ارقام فارسی (`jdate`/فیلتر `fa`) و در کد/ایمیل از ارقام لاتین.
6. **اعتبارسنجی:** `validators.py` (clamp_field، کد ملی) + `ux.css` (`.field-invalid`, `.form-error`) — خطا همیشه inline.
7. **صفحه‌ساز:** هر ویجت باید در `builder.py` + ماکروی قالب + `_sanitize_widget` نوع‌ایمن باشد؛ داده قدیمی با `d.style is mapping` گارد شود.
8. **وضعیت‌های هر مؤلفه** را طبق بخش ۹ پیاده کنید (به‌ویژه Focus/Disabled/Loading که معمولاً ناقص‌اند).
9. **موبایل:** جدول → کارت (کلاس موجود در `ux.css`)، Bottom Nav، CTA چسبان، `env(safe-area-inset-*)`.
10. **تست:** پیش از هر PR، `python -m pytest tests/ -q` و `scripts/health_check.py` را اجرا کنید.

## 📌 جمع‌بندی مفروضات مهم (طبق قانون «تصمیم‌گیری بدون سؤال»)
1. نام محصول «آکادمی آنلاین» (قابل تغییر از تنظیمات) در نظر گرفته شد.
2. نوع محصول = **پلتفرم LMS + فروشگاه دوره (SaaS)** بر اساس کد واقعی.
3. تم مرجع = **فیروزه (theme-23)**؛ سایر ۴۳ تم/۲۰ طرح به‌عنوان لایه تم روی همین توکن‌ها عمل می‌کنند.
4. مخاطب = دانشجو/مدرس/مدیر/خریدار سازمانی (۴ پرسونا).
5. «ورود» و «ثبت‌نام» در یک مسیر OTP ادغام شدند تا مراحل کاهش یابد.
6. همه‌ی صفحات بر اساس موجودی واقعی مخزن (نه از صفر) طراحی شدند و هیچ قابلیتی حذف نشد — فقط با وضعیت مشخص بازچینش شدند.
